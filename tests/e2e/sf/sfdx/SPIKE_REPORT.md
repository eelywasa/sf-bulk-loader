# SFBL-332 Spike Report — ECA + JWT Bearer Auth in Scratch Orgs

**Status:** Complete — full JWT round-trip confirmed against a real scratch org.  
**Date:** 2026-05-11  
**Branch:** `feature/sfbl-332-eca-spike`

---

## Summary

ECA + JWT bearer flow is viable as the primary path. `sf project deploy start` handles
all setup including the certificate; no manual UI steps or Apex bootstrap are required.
SFBL-324 and SFBL-327 can be implemented using the metadata shape and scripts in this
branch.

## Metadata types required (confirmed working)

| Type | Directory | Suffix | Notes |
|---|---|---|---|
| `ExternalClientApplication` | `externalClientApps/` | `.eca` | App header |
| `ExtlClntAppOauthSettings` | `extlClntAppOauthSettings/` | `.ecaOauth` | Scopes, link |
| `ExtlClntAppGlobalOauthSettings` | `extlClntAppGlobalOauthSets/` | `.ecaGlblOauth` | **Certificate lives here**; generates consumer key |
| `ExtlClntAppOauthConfigurablePolicies` | `extlClntAppOauthPolicies/` | `.ecaOauthPlcy` | Permitted-users policy |
| `PermissionSet` | `permissionsets/` | `.permissionset` | Controls JWT access |

All five types deploy cleanly via `sf project deploy start` in a plain Developer-edition
scratch org. No `ExternalClientApps` feature flag is needed in API 64+.

## Scratch-def configuration

```json
{
  "edition": "Developer",
  "features": ["EnableSetPasswordInApi"],
  "settings": {
    "externalClientAppSettings": {
      "enableConsumerSecretApiAccess": true
    }
  }
}
```

**Confirmed invalid** (causes `INVALID_INPUT` errors):
- `"ExternalClientApps"` feature flag — invalid in API 66.0
- `"ExtlClntAppSecretExposeCtl"` feature flag — invalid in API 66.0
- `externalClientAppSettings.enableExternalClientApps` — removed in API 66.0

## Key field findings

### `ExternalClientApplication`
- `distributionState`: use `Local` for scratch orgs (not `LocalAndExternal` — invalid).
- `orgScopedExternalApp` is set by Salesforce on deploy (org-specific); **never commit it**.

### `ExtlClntAppOauthSettings`
- `oauthLink` (format `OrgId:ConsumerRecordId`) is set by Salesforce on deploy; **never commit it**.
- For JWT bearer flow the certificate does **not** go here — see GlobalOauthSettings.

### `ExtlClntAppGlobalOauthSettings`
- **`certificate`**: PEM-encoded public certificate string (API 60.0+). Its presence enables
  the JWT Bearer grant flow (RFC 7523). Safe to commit — it is a public key.
- **`consumerKey`**: generated by Salesforce on first deploy; **never commit it**.
  Discover post-deploy via `discover_eca_consumer_key.sh`.
- **`isNamedUserJwtEnabled`**: controls whether access tokens are JWT-formatted. **Distinct
  from JWT bearer grant flow.** Set to `false` (opaque tokens) unless JWT-format access
  tokens are specifically needed.
- The platform **does not** auto-create this record when the ECA deploys; you must include
  it in the deploy.
- The "packaged ECAs can't deploy to scratch orgs" restriction applies only to
  `distributionState: Packaged`. With `Local`, deploy works normally.

### `ExtlClntAppOauthConfigurablePolicies`
- `permittedUsersPolicyType`: use `AdminApprovedPreAuthorized` for JWT bearer flow
  (allows pre-authorized users without a browser OAuth step).
  `AllSelfAuthorized` requires an initial browser auth — unusable in CI JWT flows.
- Valid enum values confirmed: `Local` (distributionState), `AdminApprovedPreAuthorized`,
  `AllSelfAuthorized`.

## Consumer key discovery flow (confirmed)

```bash
sf project retrieve start \
  --metadata "ExtlClntAppGlobalOauthSettings:SfblE2E" \
  --target-org "$SCRATCH_ORG"
# Parse <consumerKey> from the retrieved XML
```

The `consumerKey` field is populated in the retrieved XML after the first deploy and
remains stable for the org's lifetime. The REST connect API endpoint
(`/connect/external-client-apps/<name>`) does not exist. SOQL queries against
`ExternalClientApplication` do not expose the consumer key directly.

See `tests/e2e/sf/scripts/discover_eca_consumer_key.sh` for the complete implementation.

## Full automation flow (no manual steps)

1. `sf org create scratch` — plain Developer edition, `enableConsumerSecretApiAccess: true`
2. `sf project deploy start` — deploys all 5 metadata types including the public certificate
3. `sf org assign permset --name SfblE2EPermSet` — assigns the JWT-access permission set
4. `sf data create record --sobject SetupEntityAccess ...` — links the permission set to the
   ECA as an admin-approved accessor (required for `AdminApprovedPreAuthorized`)
5. `discover_eca_consumer_key.sh` — retrieves and parses the `consumerKey`
6. `jwt_smoke_test.sh <consumer_key> <username> <instance_url>` — confirms end-to-end auth

See `tests/e2e/sf/scripts/setup_scratch_org.sh` for the complete orchestration script.

controlled by the org's session settings.

## Surprises and divergences from spec sketch

| Spec sketch (D11) | Actual finding |
|---|---|
| `ExternalClientApp` feature flag | Invalid in API 66.0; not needed |
| `externalClientAppSettings.enableExternalClientApps` setting | Removed in API 66.0 |
| `ExtlClntAppGlobalOauthSettings` cannot deploy to scratch orgs | **Wrong** — restriction is `Packaged` ECAs only; `Local` works fine |
| Consumer key in `ClientId__c` on `ExternalClientApp` | **Wrong** — lives in `<consumerKey>` in `ExtlClntAppGlobalOauthSettings` |
| Certificate in `ExtlClntAppOauthSettings` | **Wrong** — lives in `ExtlClntAppGlobalOauthSettings.<certificate>` |
| Apex bootstrap needed for global OAuth settings | **Not needed** — `sf project deploy start` handles it |
| `ExtlClntAppSecretExposeCtl` feature flag needed | Invalid; not needed |
| `AdminsPreApproved` policy type | Invalid — correct value is `AdminApprovedPreAuthorized` |
| `SetupEntityAccess` link | **Required** — must create to activate `AdminApprovedPreAuthorized` |

## Recommendation

**ECA primary path is viable.** The full setup is automated in ~5 CLI commands with no UI
or Apex bootstrapping. SFBL-324 should adopt the metadata shape in this branch directly.
SFBL-327 should implement `setup_connection.ts` using the consumer key from
`discover_eca_consumer_key.sh` and the private key from the `SFBL_E2E_BULK_LOADER_JWT_KEY`
GitHub secret.

The Connected App fallback (D11) is not needed.
